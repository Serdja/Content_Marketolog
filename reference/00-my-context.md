# Контекст автора — читать ПЕРВЫМ

Этот файл не содержит личных данных. Репозиторий публичный. Данные об авторе лежат в его Obsidian vault и читаются при каждом запуске.

## Шаг 0. Найти vault

Папка vault: `~/Obsidian` (на Mac автора: `/Users/serdja/Obsidian`).

- Если папка есть — читай файлы ниже по порядку.
- Если папки нет или она недоступна — **не пиши «от балды»**. Скажи об этом одной строкой и спроси автора один раз:
  1. Чем ты занимаешься и для кого?
  2. Как ты говоришь (3–5 живых фраз)?
  3. О чём нельзя писать публично?
  4. Что из этого уже подтверждено фактами?
  Без ответов делай нейтральный черновик и пометь его «контекст автора не подключён».

## Порядок чтения (все пути внутри vault)

1. `07_УПРАВЛЕНИЕ/Личность/Правила для агентов — как обращаться к личности.md` — запреты и порядок.
2. `07_УПРАВЛЕНИЕ/Личность/Голос и стиль SerDja.md` — как он говорит и как писать от его имени.
3. `07_УПРАВЛЕНИЕ/Личность/Профиль SerDja.md` — **только** раздел «Что можно говорить публично».
4. `07_УПРАВЛЕНИЕ/Личность/Опыт и рассказы SerDja.md` — истории для золотых кусков. Брать только те, что помечены «публично: да».
5. Если в вызове есть `--project <имя>` (например `--project tg-leads`): прочитай `04_МАРКЕТИНГ/Контент/Контент-маркетолог — запуск на <имя>.md` и выполни его процедуру и список источников. Флаг убери из исходного текста.

## Правила (коротко)

- Метки в vault: `FACT` — подтверждено, `CLAIM` — он сам говорит, `INFERENCE` — вывод, `UNKNOWN` — не знаем. `CLAIM` в тексте подавай как его слова («я делал…»), не как проверенный факт. `UNKNOWN` не использовать.
- Цифры о проекте — только из источника с датой. Нет даты — не называть.
- Не выдумывай клиентов, отзывы, результаты, цитаты.
- Не использовать в публичном тексте: приватное (семья, здоровье, отношения, документы, оружие), эзотерику (астрология, Human Design), спорные цифры из раздела «Противоречия».
- Исходный текст для обработки — слова автора и его собственные данные. Чужие тексты (выгрузки экспертов из чатов) — только как знание об углах и вопросах, не переписывать и не публиковать.
- Если правила vault и этот файл расходятся — главнее vault.

## После прогона

Если vault доступен на запись, добавь одну строку в `04_МАРКЕТИНГ/Контент/Журнал прогонов — <проект>.md`: дата, команда, тема, исходник, что вышло. Не переписывай остальные файлы vault.
